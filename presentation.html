What is silo?

A CLI tool that runs AI coding agents in isolated containers and lightweight VMs — so they get full access without touching our machine.

// the problem

AI agents need broad access

  • They read files, run commands, modify code
  • Permission prompts put us back in the loop — approving, reviewing, approving
  • To really leverage them, we need them unblocked
  • They work best when we turn off permission prompts — "yolo mode"
// the tension

The fundamental tradeoff

Full access
Maximum capability
↔
Restricted
Reduced utility

Give them access and accept the risk, or restrict them and lose the thing that makes them useful.

// sandboxing

Sandboxing

  • OpenAI Codex CLI shipped sandbox mode first, then Claude Code added it
  • Experimented with macOS sandbox-exec and custom rules
  • Hard to get right — build caching broke, Go build cache errors, flaky tool behavior
  • Often falls back to the permissions list anyway — only a small edge

If you're not using any isolation right now, turn on sandboxing in Claude Code. It's the best place to start — good safety with minimal effort.

// remote

Remote

  • Claude web, GitHub Copilot coding agent — run the agent on someone else's infrastructure
  • Great for long-running investigative tasks like bug finding
  • Good for completely hands off, arms length spikes
  • Kick off work remotely, then continue later locally
  • Tradeoff: machines we don't control, without tools we have locally, and often limited
// containers

Containers

  • Real isolation — the agent gets full access inside a throwaway environment
  • No permission lists, no fragile sandbox rules

// backends

Two isolation backends

Docker

  • Works on any platform
  • All containers share one Linux VM
  • Container isolation (shared kernel)
  • Docker inside = shared engine, easy breakout

Apple Container

  • macOS only
  • Each container = its own VM
  • VM isolation (own kernel)
  • Docker inside = own engine, fully isolated

Auto-detected: uses Apple Container if installed, falls back to Docker.

// repos

Repository-aware config

// Apply settings by git remote URL
"repos": {
  "github.com/myorg": {
    "env": ["ORG_API_KEY"],
    "post_build_hooks": ["npm i -g @myorg/cli"]
  },
  "github.com/myorg/special": {
    "env": ["SPECIAL_TOKEN"]
  }
}

Substring matching on remote URLs. Multiple matches merge by specificity (shortest pattern first).
